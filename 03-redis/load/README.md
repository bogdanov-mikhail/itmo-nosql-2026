# k6-профили нагрузки

Запуск: `make load PROFILE=<smoke|burst|fair|platform>` из каталога `03-redis/`.
Вывод каждого прогона сохраняется в `load/results/<profile>-<время>.txt`.
Между прогонами выдерживать паузу ≥ 60 с — бакеты должны опустошиться/восстановиться.

Тарифы per-client лимитера (значения по умолчанию): `free` — 10 rps, burst 20;
`standard` — 50 rps, burst 100. Глобальная квота: 300 rps (`GLOBAL_LIMIT_FOR_PERIOD`).

| Профиль | Схема | Ожидание |
|---|---|---|
| `smoke` | 1 standard-клиент, 5 rps, 30 с | все 200 |
| `burst` | free: мгновенные 30 параллельных (capacity 20), затем 25 rps 20 с | в burst ~20×200 и ~10×429 `client`; в steady разрешено ≈10 rps, остальные 429 `client` |
| `fair` | heavy standard 120 rps + light free 5 rps, 20 с | light 100% 200; heavy ≥50% 429 `client` (бакет standard честно ограничивает только heavy-клиента) |
| `platform` | 8 параллельных источников × 60 rps = 480 rps, 20 с | часть 429 `platform`, 5xx нет. На время прогона тариф standard поднимается до 1000 rps (`make` пересоздаёт app с override и возвращает конфиг обратно), иначе per-client лимит не пускает дальше 50 rps и глобальная квота недостижима |

Отклонения фактических чисел от ожиданий фиксируются в сводке прогона и в
главе README «Нагрузочное тестирование» — не сглаживаются.
